## What is low-level

关注图像的像素、结构和外观，这里主要讨论图像恢复与增强，当然包括边缘提取，风格化等等。

## Problems in low-level

1. 图像恢复大多是病态问题，仅凭退化图像难以确定原图，需要引入先验或额外观测
2. 重视像素级别的细节（PSNR, SSIM），但像素准确与视觉真实并不等价，PSNR和SSIM不能完全反映感知质量
3. 退化很多样，当测试时的退化超出训练分布，会面临 OOD 的问题
4. 干净配对数据难以获取，需要减少对配对监督的依赖

## Methodology

以上的问题就引出了如下的几种典型方法：

1. 引入物理先验、视频相邻帧信息，或从数据中学习恢复先验。[[QuadPrior]], [[SLDNet+]], [[DiffIR]], [[WeatherDiff]]
2. 从像素重建到感知与对抗目标，权衡重建准确性与纹理真实感。[[SRCNN]], [[SRGAN]]
3. 通过多阶段结构、卷积和注意力机制，兼顾局部细节、上下文信息和计算成本。[[MPRNet]], [[SwinIR]]
4. 利用物理约束或时序自监督，减少对干净配对数据的依赖。先验与自监督可以结合。[[QuadPrior]], [[SLDNet+]]
5. 追求 all-in-one 的统一模型，通过视觉提示指定处理任务，但多任务能力不等于 OOD 泛化能力。[[GenLV]]

## From Papers

以下是跨论文比较后的理解，而非各篇论文结论的直接复述。

### 上下文从哪里来，细节在哪里保留

多尺度、多阶段的意义在于扩大可用上下文，同时控制空间细节的损失。[[MPRNet]] 前两阶段使用多尺度结构，最后保持原分辨率；[[SwinIR]] 去掉逐级 Patch Merging，通过窗口与移位窗口交换信息。两者说明，获得上下文不必只有降低分辨率这一条路。

读结构时可以分别追踪上下文与细节的传递路径：MPRNet 的 CSFF、SwinIR 的残差连接、[[QuadPrior]] 的 bypass decoder，都在不同位置帮助保留或复用信息。“局部与全局”也应区分空间作用范围和语义层次：利用全图统计或跨窗口交互，并不自动意味着理解了全局语义。

### Prior 提供什么，又如何进入模型

“引入先验”需要进一步回答：先验从哪里来，排除了哪些可能解，以什么形式作用于恢复，以及在什么条件下失效。

| 信息来源 | 作用与例子 |
| --- | --- |
| 物理假设 | QuadPrior 构造近似光照不变的表示，尝试连接低光与正常光域 |
| 数据中学到的规律 | 生成模型提供自然图像分布；[[DiffIR]] 学习用于调制恢复网络的紧凑表示 |
| 时间上的结构假设 | [[SLDNet+]] 利用对齐后背景相对稳定、雨条纹随机变化的性质 |
| 额外观测 | 邻帧可能提供当前帧被遮挡的内容；邻帧本身是观测，共享背景才是假设 |

还应区分信息的来源与注入方式：损失约束、特征调制、条件分支和跨帧融合承担不同作用。实际观测提供的细节，与生成先验补出的合理细节，具有不同的证据基础。

### 建模：解释退化，也选择学习的映射

我更关注如何提出有解释力的问题和假设，以及它们如何导出解法。物理建模从观测形成机制出发，例如 SLDNet+ 区分雨条纹叠加与雨雾的衰减、散射，为分步恢复提供依据。但写出退化方程不等于问题已经可解：未知量可能多于观测，还需要先验或额外信息来约束解。

另一种建模是选择网络实际学习什么。QuadPrior 将低光增强改写为 prior-to-image；DiffIR 在紧凑先验空间进行扩散，再由恢复网络重建；[[WeatherDiff]] 则直接在图像空间迭代恢复。可以追问：哪些部分需要生成模型，哪些部分可以由一次前向的网络完成？

架构能力会启发映射设计，但并不唯一决定映射。QuadPrior 的映射同时受到物理不变性的启发。仅凭论文最终呈现的逻辑，也无法确定作者实际先想到架构还是问题。

值得积累的研究能力是区分**问题的必要条件与已有方法的设计选择**。恢复是否必须直接预测图像？获取上下文是否必须降采样？这些问题可以在改进已有方法的过程中，带来对问题本身的重新表述。相关讨论见 [[Diffusion Models#从方法改进到问题重构]]。

### 减少监督依赖，意味着寻找替代约束

不使用干净配对 GT 后，需要说明什么信息仍然约束着结果。SLDNet+ 依赖对齐与可靠非雨区域；QuadPrior 依赖跨光照表示近似一致，以及正常光数据和预训练生成模型。

因此，“无需配对”之后还应继续检查替代约束的适用范围。大幅运动、遮挡、极低信噪比或复杂光照，可能破坏这些条件。多任务训练同样不能替代泛化证据：[[GenLV]] 能通过 prompt 指定任务，并不意味着它能可靠执行未见任务。

### 质量与一致性有多个层面

[[SRCNN]] 与 [[SRGAN]] 展示了像素重建与纹理真实感的取舍。除此之外，还需检查输出是否忠实于输入内容、分块边界是否协调、视频是否闪烁，以及是否执行了指定任务。

WeatherDiff 在每一步融合重叠图块的噪声预测，再统一更新整图，说明局部预测之间如何协调也可以是方法的核心。生成了合理纹理，并不保证恢复了真实丢失的细节。

### 简化与近似：保留什么，放弃什么

实际过程包含很多耦合因素，求解常常需要激进的简化。困难在于事先判断哪些因素可以忽略，哪些会牵动整个系统。一个简化应尽量明确：

1. 希望保留的关系、信息或能力是什么？
2. 放弃了哪些现象的解释能力？
3. 在什么条件下，被忽略的因素会主导结果？

例如，QuadPrior 希望消除光照影响并保留内容，但不变表示可能丢失有用信息，在低光噪声下也可能不稳定。因此，更强的不变性不必然对应更好的恢复效果，需要同时检查跨域对齐与内容保留。

还要区分人为设计、精确变换、依赖条件的近似，以及经验性的训练选择。它们需要不同的论证，失败后的排查方向也不同。[[DDPM#建模与简化的层次]] 是一个具体例子。

### 实验与复盘：定位推理链中失效的环节

一次效果不好，可能来自假设不成立、近似过粗、表示丢失必要信息、优化失败，或者评价没有测到预期收益。只看最终指标，很难区分这些解释。可以先写出方法的推理链：

> 假设成立 → 表示具有预期性质 → 模型能利用这种性质 → 输出改善。

再为中间环节安排诊断，而不只反复修改整个网络。以下是可考虑的实验，并非这些论文都已完成的验证：

| 需要区分的问题 | 诊断方式 |
| --- | --- |
| 先验本身是否有用？ | 在明确使用额外信息的诊断设定下，提供理想或更准确的先验，检查恢复潜力 |
| 问题是否来自先验估计？ | 比较理想先验与实际预测先验的结果 |
| 下游是否过于敏感？ | 对先验施加逐渐增大的受控扰动，观察输出退化 |
| 核心假设何时失效？ | 分别控制噪声、光照、运动等因素，寻找失效边界 |
| 收益是否来自声称的机制？ | 控制 backbone、数据和训练预算，比较相应机制；必要时在多个 baseline 上验证 |

例如，若理想先验有效，但轻微估计误差就使收益消失，下一步可能应研究误差容忍度。若声称表示具有光照不变性，则应直接比较同一场景不同光照下的表示，而不能只看最终增强指标。

模块之间还会互相适应和补偿。“移除模块后重新训练”检查系统能否适应替代设计；“固定模型并扰动模块输出”检查当前系统对该模块的依赖，两者回答不同问题。[[DiffIR]] 中对 prior 跨 baseline 验证的疑问，以及 [[GenLV]] 中框架与 backbone 的对照，都属于让证据对应具体主张的思考。

研究仍然有探索性，但应尽量让每次实验减少对失败原因的不确定性。没有提升指标、却排除了关键解释的实验，也能帮助修正对问题的理解。
